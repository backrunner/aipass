# Native 0.3.0 CI repair

The product version is 0.3.0 across the Rust workspace/lockfile, root package,
native desktop metadata/package and browser extension package/manifest.
This change does not create a release tag or publish artifacts.

## Failure and repair

PR CI run [43702745715](https://github.com/backrunner/aipass/actions/runs/43702745715)
at `2fc4f5abe610e5c8a980fd572c09e0bd49bf8295` passed Node and macOS bundle jobs,
but failed Linux and Windows compilation. The classic tray called private
`muda::MenuItemKind::as_ref`; clearing now uses the public indexed removal API.
Unix-only imports and lease constants are gated from Windows builds, and the
unused vault `anyhow` manifest entry is removed.

The next run reached a Windows-only must-use diagnostic in the updater handoff.
The desktop now explicitly drops the path returned by `TempDir::keep`; the
directory remains retained for the independent helper, which owns cleanup.

The Linux packages then built successfully and passed CLI/native credential
import and GPUI/Agent probes, but the startup-complete assertion caught a real
bootstrap gap. Hidden/occluded X11 windows need not receive another frame;
startup/update activation now uses a window-deferred callback after GPUI's
synchronous initial draw, rather than waiting for a platform frame. Both the
production and isolated parity updater paths use this ordering. The existing
startup-complete assertion remains in place.

The Linux real-Agent roundtrip also caught generic tool rollback being parsed
as a native-account switch response. The native UI now decodes the Agent's two
existing typed response shapes separately, shows successful file restoration,
and preserves native conflict/login-required states. Regression covers both
wire shapes and the restore notice. The disposable CLI fixture also uses a
Windows command shim and platform-correct PATH separators.

Review of the next platform-specific gates also found and fixed:

- Windows NSIS passive replacement `/P` and legacy `/AIPASS_REPLACE` handling.
  Replacement preserves proxy backups while draining owned processes; ordinary
  uninstall still restores configurations. Registry commands use correct quoting,
  and installer compilation now treats warnings as errors.
- AppImage packaging explicitly passes the downloaded, hash-verified runtime via
  `--runtime-file`. The pinned tool does not read our environment variable;
  missing runtime configuration now fails before staging. See the
  [upstream argument definition](https://github.com/AppImage/appimagetool/blob/1.9.1/src/appimagetool.c).

## Cargo artifact discovery

The remote Rust 1.100 run passed workspace regression, including generic file
rollback, then exposed a hard-coded `target/debug/deps` assumption in the Linux
credential-store harness. CI now retains Cargo's compiler-artifact messages
from that test invocation; the harness selects the exact library test binaries
from their reported paths, preserving all credential-store assertions. Parser
regression covers old/new/custom layouts and missing/ambiguous outputs. This
uses Cargo's [documented JSON interface](https://doc.rust-lang.org/cargo/reference/external-tools.html),
not an assumed build-directory layout. Node setup now precedes Node checks in
the Rust job.

## AppImage restart identity

The packaged Linux main/tray and integration checks passed, then installation
exposed a readiness PID mismatch. The pinned AppImage runtime forks AppRun and
waits for it in extract-and-run mode; the desktop reports its own PID, not the
runtime wrapper PID. The updater now checks the kernel process-parent chain for
AppImages only. It accepts the spawned process or a live same-user descendant,
rejecting unrelated, missing, dead, foreign-user and cyclic identities. Direct
package executables retain exact-PID matching. Signature validation, the private
staging handshake, inherited instance lease and rollback remain required.

Source: [pinned AppImage runtime](https://github.com/AppImage/type2-runtime/blob/20251108/src/runtime/runtime.c#L1618-L1659).
Local parser/ancestry regressions cover the decision paths; actual AppImage
installation remains verified by the native Linux CI job.

The Cargo artifact parser passed both synthetic layout/error cases and real
macOS Cargo JSON output for the two credential-test executables. Node lint/tests,
repository policy, skill validation and CI YAML parsing passed. The AppImage
identity parser's two portable tests and root strict Clippy passed; a live
Linux child/ancestor test is included for CI. These Linux-only production
changes reuse the unchanged macOS runtime evidence. Run 43732077140 also passed
the full macOS bundle/runtime job and Node job on GitHub Actions.

## Windows isolated profile

The retained startup diagnostic identified `Windows profile is unavailable`
inside named-pipe ownership setup. The provider fixture redirected USERPROFILE,
APPDATA and LOCALAPPDATA but omitted the two AppData directories. Windows
Known Folder lookup verifies existence, so the fixture now creates both before
spawning the client/Agent. The CLI and installed-runtime fixtures already do
this. Production pipe ownership, ACLs and profile validation are unchanged.

Reference: [Windows Known Folder flags](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/ne-shlobj_core-known_folder_flag).
Run 43733387049 passed the complete Linux Rust job, including workspace Clippy,
regression, isolated credential stores, build and startup without systemd.
