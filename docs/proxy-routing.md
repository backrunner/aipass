# 跨品牌路由组

在本地代理中创建或编辑路由组，启用「绑定成员模型」，为每个启用的成员填写
实际上游模型。成员可以来自不同品牌，也可以混合本机 CLI 订阅与 API Key。
客户端使用编辑器显示的 `group/<路由组 UUID>`，以及该组自己的本地 token。
`GET /v1/models` 使用同一个 token 时会返回这个组模型。

例如，一个组可以包含 Claude、Codex、Grok Build 的独立订阅账号，以及 API Key。
每个成员填写该账号实际模型目录中的名称；模型是否可用由上游账号与套餐决定。
AIPass 不推测不同名称的模型是否等价。

处理顺序：本地 token 确定组 → 策略选择成员 → 替换为成员实际模型 → 按该成员
的协议、账号和传输方式发起请求 → 转换为入口协议的响应。入口支持 OpenAI
Responses、Chat Completions 和 Anthropic Messages。成员实际协议由 Rust Agent
解析，必要的协议转换自动启用。HTTP 和 Responses 下游 WebSocket 使用同一模型
映射；订阅上游仍使用其原有 CLI 桥或原生 HTTP 传输。

组沿用顺序回退、加权轮询和按额度选择策略，并保留会话粘性、并发限制、熔断及
生成提交后的禁止重放规则。按额度选择匹配成员实际模型的额度窗口。用量和价格
计算也记录实际成员模型；组目录不虚构所有成员共有的上下文长度、价格或能力。
不同成员需要能表达客户端所用的工具、内容和推理语义，否则请求明确失败。

## 会话边界

普通完整历史可以在成员之间转换。Claude 的等待中工具会话、Gemini 工具签名、
Anthropic 签名 thinking、Responses 的加密推理及服务端 conversation 状态需要
保留原账号。已记录的来源不可用时，不把这些状态发给其他账号；没有来源记录
的状态返回错误，客户端需要重新发送可移植的完整历史。来源记录有容量及有效期
限制，代理重启或成员模型/账号更改后可能需要建立新会话。

跨品牌模型映射会修改请求，不能称为逐字节透明转发。未绑定成员模型的旧路由
保持既有行为，继续使用客户端传入的模型。同一品牌可以配置多个独立订阅账号，
通过相同策略选择；混组也支持多个品牌各自的多个账号。

图片生成/编辑端点使用独立的图片路由，不接受组模型。嵌套组、按任务意图选模型
和自动猜测模型等价关系不属于当前路由契约。

## 配置与维护

每个 `ProxyTargetConfig` 的可选 `model` 是成员模型绑定；不填写表示使用客户端
模型。一个启用成员填写了 `model` 后，组内其他启用成员必须同时填写。Rust Agent
在持久化前校验非空、无控制字符、首尾无空格且不超过 256 字节。已有 JSON 配置
无需迁移。桌面与局域网面板共用编辑器，CLI 的 `proxy config-set` 及 MCP 的组配置
同样通过 Rust Agent 保存与校验。快速写入 CLI 配置会自动使用组模型。

订阅认证仍归官方 CLI 管理，路由组只绑定账号引用和模型，不保存 OAuth 凭据。
实现和回归由 AIPass 原生 Rust 模块维护。关键模块为 `aipass-proxy/model_routes`、
`forward/prepare`、`selection` 和 Agent 的 `proxy_service/config`、`runtime`。

回归覆盖跨协议回退、API → 订阅回退、模型发现、模型额度筛选、历史来源约束、
连接状态失效、大请求转存及 HTTP/下游 WebSocket 模型映射。真实订阅模型可用性、
实时额度和扣费仍需对应账号的实测，fixture 不提供这些证据。
