# 更新

AIPass 通过两个渠道发布，均经由 GitHub Releases 分发，并使用 Tauri updater 消费：

- **官方（Official）** —— 标记为 `vX.Y.Z` 的稳定版本。更新订阅源：`https://github.com/backrunner/aipass/releases/latest/download/latest.json`，始终指向最新的稳定版本。
- **Beta** —— 供早期测试的滚动预发布版本，以 `beta` 预发布形式发布在同一仓库。更新订阅源：`https://github.com/backrunner/aipass/releases/download/beta/latest.json`。Beta 构建可能包含未完成的功能。

每个订阅源都是随对应 GitHub Release 一起发布的更新清单；构建产物经过签名，应用在安装前会验证签名。

## 我在哪个渠道？

默认渠道跟随当前安装的构建：版本号中包含连字符（例如 `0.9.0-beta.3`）的构建从 **Beta** 渠道开始，纯 `X.Y.Z` 版本从**官方**渠道开始。一旦你手动修改过，选择会按机器保存，应用更新后仍然保留。

## 更新面板

**设置 → 更新**显示当前版本、所选渠道和手动的**立即检查**按钮。发现更新时可就地安装；应用前会验证签名。

## 切换渠道

在桌面应用中：**设置 → 更新 → 更新渠道**提供**官方**和 **Beta** 两个选项。切换会保存选择，并立即在新渠道上重新检查更新——如果另一渠道有更新的构建，安装按钮会立刻出现。

你也可以从[下载区](/)或 [GitHub Releases](https://github.com/backrunner/aipass/releases) 直接下载目标构建覆盖安装来切换渠道。无论哪种方式，保险库都不受影响。

## 自动更新的行为

- 应用在启动后不久（3 秒延迟）检查更新，最多每 24 小时一次，读取当前渠道的清单。
- 发现更新的构建时，应用内横幅提供**安装并重启**——下载、验证并就地应用更新——或**稍后**——跳过该版本；AIPass 不会就同一版本再次提示。从**设置 → 更新**手动发起的检查总会执行，并会显示后台检查中静默处理的错误。
- 后台检查失败（离线、被限流）是静默的；检查未完成不会影响任何功能。

## 下载页与渠道

本站的[下载区](/)总是优先选择带有 macOS 安装包的最新**官方**版本。只有当尚无带安装包的官方版本时，才回退到 Beta 构建，并在版本号旁标注渠道。Windows 构建标注为 **Coming soon**。

## 面向发布维护者

两个订阅源都只是名为 `latest.json` 的 GitHub Releases 资产——官方订阅源借助 GitHub 的 `latest` 别名，Beta 订阅源挂在 `beta` 标签上。发布新版本（或更新 `beta` 预发布）就会为该渠道的所有已安装应用更新订阅源；无需运行独立的更新服务器。
