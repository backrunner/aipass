# Microsoft Edge 加载项提交清单

依据 Microsoft Learn 的“发布 Microsoft Edge 扩展”流程准备。可上传包为 `apps/extension/build/aipass-extension.zip`；Release 工作流会将同一包发布为 `aipass-edge-extension.zip`。

## Partner Center 填写顺序

1. **上传包**：上传 ZIP，确认 `manifest_version: 3`、版本号和 `default_locale: en` 正确。
2. **可用性**：首发建议选择 Public；市场按发行范围选择，默认可选所有市场。
3. **属性**：类别选 Productivity；网站填 `https://aipass.alkinum.io/`；支持填 `https://github.com/backrunner/aipass/issues`。
4. **隐私**：按 [privacy-disclosures.json](privacy-disclosures.json) 填单一用途、权限理由、无远程代码、数据使用和隐私策略 URL。隐私策略填 `https://aipass.alkinum.io/docs/security`。
5. **Microsoft Store 一览**：按 [listing.md](listing.md) 填名称、简短说明、描述和搜索词。描述约 1,900 字符，满足 250 字符最低要求。
6. **图像物料**：上传 `assets/edge-logo-300.png`（必需）、`assets/edge-tile-small-440x280.png`、`assets/edge-tile-large-1400x560.png` 和两张 1280×800 PNG 截图。
7. **认证说明**：复制 [certification-notes.md](certification-notes.md)，将 `{{EDGE_EXTENSION_ID}}` 替换为 Partner Center 分配的实际扩展 ID，再提交认证。

## 权限对齐

- `activeTab`：用户打开弹窗后读取当前页面 URL/标题，用于上下文匹配。
- `alarms`：Native Messaging 连接断开后的重连计时。
- `nativeMessaging`：与本机 AIPass agent 通信；凭据不走云端。
- `scripting`：用户明确执行填充/扫描时注入已打包的脚本。
- `storage`：仅保存 session 缓存、已忽略来源和 UI 状态，不保存 API key 或主密码。
- `<all_urls>`：在服务商控制台运行检测和填充脚本；用户可按来源关闭检测。

## 提交前检查

```bash
node scripts/set-extension-release-version.mjs 0.1.0
pnpm --filter @aipass/extension build
pnpm --filter @aipass/extension test
pnpm --filter @aipass/extension typecheck
pnpm --filter @aipass/extension edge:validate
```

商店发布 ID、Native Messaging allowlist、真实 Edge 安装/填充和 Partner Center 认证结果无法在代码仓库内自动完成，需在上传包后补做。
